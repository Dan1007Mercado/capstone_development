# P13.5.2 Selected-Template Page Resolution

## Scanner identity model

The user selects one immutable published `TemplateId` and `TemplateVersion`
before opening the camera. That `PublishedScannerArtifact` remains fixed for the
session and supplies every candidate `PageLayout`. The camera does not search
other templates or versions.

Physical page identity comes only from the selected artifact's page-specific
ArUco signature. A live frame is accepted as a page match only when each of the
four expected IDs occurs exactly once. Partial, mixed, duplicate, and unknown
sets remain unresolved and cannot become capture-ready.

## Marker allocation

`PageMarkerIdAllocator` is the only allocator. Starting with the configured
page-one roles, the page index adds four while preserving role order:

- page 1: TL 10, TR 11, BL 12, BR 13
- page 2: TL 14, TR 15, BL 16, BR 17
- page 3: TL 18, TR 19, BL 20, BR 21

`PageLayout.markerRegions` owns the resulting IDs. PDF rendering, live camera
analysis, and final alignment consume those IDs without recalculating them.
Marker bounds, quiet zones, and registration points are unchanged.

DICT_4X4_50 contains IDs 0 through 49. With allocation beginning at 10, the
maximum is ten pages. Page 11 fails layout with
`ARUCO_PAGE_ID_CAPACITY_EXCEEDED`; IDs never wrap.

## Live and final resolution

The persistent camera worker owns one reusable native ArUco detector and a
cached `PageMarkerSignatureResolver`. Each accepted frame is downscaled and
detected once. The resolved signature selects the active `PageLayout`, whose
role mapping then drives geometry and the overlay.

The high-quality still runs native detection again. Alignment requires its IDs
to equal the live-selected page signature exactly before correspondence or
homography. A mismatch returns `SCAN_UNKNOWN_PAGE_MARKERS`; duplicate IDs return
`SCAN_DUPLICATE_PAGE_MARKERS`.

## Session behavior

`ScannerValidationSession` stores `Map<PageId, ScanResult>`. Pages can therefore
be scanned in any order. A page already in that map is not auto-captured and is
reported as `SCAN_PAGE_ALREADY_COMPLETED`. The session is complete only when
every `PageId` in the selected artifact has a result.

## QR removal

Production scanner composition no longer contains a QR identity stage, QR crop
or upscale fallbacks, or full-page QR decoding. Generated survey PDFs no longer
render a QR widget. The reserved identity/header geometry is intentionally left
unchanged. No barcode was added.

## Performance findings and hardening

The removed QR fallback could perform several decode attempts at increasing
sizes and was an avoidable final-scan latency source. Live ArUco detection is
still performed only once per accepted frame, and both the native detector and
page resolver are reused by the worker isolate.

Bubble measurement previously allocated and sorted grayscale lists for every
interior and baseline. It now uses fixed 256-bin histograms, a running sum, and
rank interpolation with the same percentile semantics. Baseline neighbor
candidates are precomputed with a conservative circle-intersection rejection,
so each baseline pixel is no longer tested against every bubble on the page.

The OpenCV preprocessing path was reviewed. Its clipped-window divisor is
necessary to preserve the Dart reference's edge behavior, so it was not
replaced with a border mode that would change pixels. It already keeps filtering
and statistics native, returns detached buffers once, and consumes canonical
grayscale directly without PNG transport. Stage timings remain exposed so
device measurements can identify whether denoise, illumination normalization,
thresholding, or statistics dominates before a semantic change is considered.

Diagnostics separately expose readiness-status time, first recognition to
ready, stop-analysis, still capture, byte load, decode, ArUco detection, page
resolution, correspondence, homography, warp, preprocessing stages, bubble
measurement, classification, validation, isolate overhead, and total
capture-to-result time.

## Accuracy findings

The recognition policy remains conservative: bubble outlines are excluded by
the inset interior, nearby known bubbles are masked from the local baseline,
and weak or competing evidence stays ambiguous instead of selecting the darkest
option. Existing synthetic coverage exercises blank, pencil-like, partial,
multiple, neighboring-bubble, outline, gradient/uneven-lighting, and quality
cases. P13.5.2 does not loosen classification or image-quality thresholds.

## Android validation

Manual Infinix validation is still required. Record first-recognition-to-ready,
each readiness-state duration, stop-analysis, capture, byte load, every final
scanner stage, and capture-to-result. Also confirm page 2 can be scanned first,
a repeated page 2 is blocked, remaining pages complete in any order, and no QR
is present or required.

## Non-goals

- no global template identification
- no barcode or QR fallback
- no P14 persistence/integration
- no dense A4, marker-size, bubble-size, or threshold tuning without device
  evidence
