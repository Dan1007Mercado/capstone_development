# p14.1 — Dense Predictable OMR Layout

## Why p14 needed refinement

p14 introduced the right production structure: deterministic physical and
normalized geometry, adaptive 2/3/4-column candidates, atomic measured
questions, section continuation fragments, multi-page flow, numeric-grid and
long-label modes, geometry validation, and shared `PageLayout` consumption by
PDF and scanner code. Its default dense policy nevertheless looked like a
generic survey form. In particular, short Yes/No and Likert questions could
put bubbles beside the prompt, the 6 mm column gap wasted width, question
numbers were absent from measurement and rendering, and page count dominated
candidate cost.

p14.1 keeps that architecture. No p14 engine or recognition component was
replaced.

## Old dense baseline

`buildP13_6DenseValidationInputs()` is the permanent two-column golden dense
reference. It deliberately fixes the adaptive dense configuration to two
columns so the 40-question/160-bubble scanner-layout fixture remains stable.
Production dense templates still evaluate the p14 2/3/4-column candidates.

The golden's purpose is deterministic ordering, compact A4 use, 5 mm bubbles,
no overlap, and identical PDF/scanner geometry. p14.1 does not promise numeric
identity with every pre-p14 coordinate because the column gap and numbered
prompt grammar were intentionally improved.

## Dense question grammar and wrapping

Ordinary dense questions use `QuestionRenderMode.stackedHorizontal` whenever
their option row fits:

```text
16. Who's the commander of something?

    ○ Yes    ○ No
```

The prompt region is measured and placed first. The bubble row begins below
`promptRegion.bottom` with the configured 1.5 mm minimum content gap. Wrapped
prompt lines increase `promptRegion` and the complete prompt finishes before
any bubble is placed. The whole measured question remains atomic when flow
advances to another column or page.

Long option labels continue to use `stackedVertical`. Numeric grids continue
to use `numericGrid`; neither is converted into a normal bubble row. The
comfortable profile retains the p14 inline mode where appropriate, but the
dense profile does not select it.

Text measurement remains the existing deterministic character-width estimate,
not font shaping. PDF rendering uses the authoritative prompt bounds and does
not perform a second geometry calculation. Perfect hanging indentation is
therefore deferred rather than introducing renderer-dependent layout.

## Global question numbering

`LayoutEngine` assigns one-based numbers in exact template section/question
order before measuring each question. Measurement uses the actual display
prefix (`"16. "`) together with the semantic prompt. `QuestionRegion` stores
the assigned number, and `PdfEngine` renders that same number in the
`questionPrompt` command. Numbering therefore remains deterministic across
sections, columns, and pages and cannot create a PDF-only wrapping prefix.

Published-layout artifact encoding includes `questionNumber`. Decoding remains
compatible with older artifacts by treating an absent number as legacy value
zero; legacy PDF plans then retain their unnumbered prompt instead of inventing
geometry after publication.

## Sections and flow

Section titles remain compact measured lead regions. A section does not reserve
a column. Questions flow top-to-bottom through each column and then to the next
page without reordering. A continued section preserves its `SectionId` and does
not repeat title, instruction, or human-readable field regions. Questions,
prompt rows, option groups, and numeric grids are never split.

## Column policy and physical values

The dense A4 profile uses:

| Setting | p14.1 value |
| --- | ---: |
| Candidate columns | 2, 3, 4 |
| Preferred columns | 3 |
| Inter-column gap | 4.5 mm |
| Minimum allowed gap | 4 mm |
| Minimum column width | 34 mm |
| Bubble diameter | 5 mm |
| Bubble horizontal gap | 1.5 mm |
| Bubble vertical gap | 2 mm |
| Prompt-to-bubble/content gap | 1.5 mm |
| Question vertical gap | 1 mm |
| Section gap | 3 mm |
| Preferred/maximum prompt lines | 2 / 6 |
| Maximum prompt lines for normal column placement | 3 |

All values remain centralized in `LayoutConfig` or
`LayoutSelectionPolicy`. Bubble size is not reduced to gain density.

Only candidates that pass configuration, geometry, readable-width, wrapping,
marker-exclusion, and bubble-safety checks can win. Valid candidates are then
ordered deterministically by:

1. fewer excessive prompt wraps;
2. fewer full-width fallbacks;
3. fewer stacked-vertical fallbacks;
4. distance from the preferred three columns;
5. page count;
6. unused area;
7. continuation count;
8. column count as the final stable tie-breaker.

This means two columns can beat three when the wider lanes materially improve
prompt behavior, while four columns cannot win merely by saving a page.
`LayoutCandidateDiagnostics` now records column width, gap, bubble diameter,
page count, unused area, all/excessive wrapping counts, vertical and full-width
fallbacks, section fragments, continuations, render-mode counts, rejection
reasons, and cost.

## Shared PDF and scanner geometry

`PageLayout` remains the single source of physical and normalized geometry.
`PdfRenderPlan.page.layout` is the generated page object; PDF bubbles are the
page's `bubbleRegions`; question text uses `QuestionRegion.promptRegion`.
`CameraScanContext` receives that same page and candidate page list, and the
offline scanner and bubble measurement stages continue to consume its bubble
regions after canonical alignment. No PDF-only, camera-only, or raw-pixel
layout copy was introduced.

## Regression coverage

The old dense tests retain the 40-question, two-column, 160-bubble golden.
p14 tests retain adaptive candidates, long prompts/options, numeric grids,
atomic flow, section continuation, geometry safety, deterministic output, and
shared PDF/scanner contracts. The p14.1 suite adds:

- dense prompt-above-bubble structure for Yes/No and Likert;
- numbering-sensitive prompt measurement at the 9/10 boundary;
- global numbering across sections, columns, and multiple pages;
- preferred three-column and wide two-column behavior;
- 4.5 mm gap and expanded candidate diagnostics;
- exact numbered PDF prompt text and prompt bounds;
- `CameraScanContext.validate()` for every page of an 80-question layout;
- identical camera `PageLayout`/bubble object geometry;
- PDF generation for a realistic multipage dense template.

The p14 60-question page-count assertion was intentionally changed from two to
three pages because dense prompts now always finish above their bubble rows.
That additional page is the explicit readability tradeoff required by p14.1.

## Physical validation still required

Automated geometry and contract tests do not establish real-world OMR quality.
Before production claims, print at actual size and scan:

- two- and three-column sheets;
- four-column sheets if that candidate is enabled for release;
- 5 mm bubbles with pencil, black/blue pen, faint marks, checks, crosses,
  partial fills, erasures, and multiple marks;
- uniform/dim light, shadows, glare, blur, rotation, page tilt, perspective,
  and incomplete page edges;
- multiple printers, quality settings, grayscale modes, and printer scaling;
- multiple Android camera devices.

The existing deterministic text-width estimate and unvalidated four-column
physical readability are the main remaining layout risks. A later physical
validation phase should tune policy values from measured print/scan evidence,
without changing the shared `PageLayout` contract.
