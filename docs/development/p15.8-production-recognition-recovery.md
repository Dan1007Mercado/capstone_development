# P15.8 Production Recognition Recovery

## Scope and evidence

This change was developed from commit `e8db7510e09e49757c68294b7172691946e44049` on branch `implementation/p15-8-recognition-recovery`. It replays the unchanged P15.6 published artifact and the six physical JPEGs from `images_samples` in Android profile mode on the Infinix X6711. The packet was printed with fit-to-page scaling. The compact machine-readable result is in [native_profile_summary.json](evidence/p15_8/native_profile_summary.json).

The expected marked answers supplied for the two answer patterns were:

- fully marked: `1, 4, 5, B, A, C, A, B, B, A, A`
- mixed stroke: `1, 4, 2, A, A, B, B, A, A, B, A`

## Root cause

The P15.7 evidence showed that a globally valid ArUco homography did not place every printed bubble center closely enough for the small inner measurement masks. The four usable physical captures had mean source-to-expected bubble offsets from 5.446 to 9.816 pixels and p95 offsets from 11.582 to 18.453 pixels. This is much larger than the mark evidence lost when the sampling mask lands on the printed outline or label exclusion region.

The failure is a residual print/capture registration error after page homography. It varies smoothly by row and column and is consistent with fit-to-page printing plus paper/camera distortion. Classification thresholds were operating on the wrong pixels; changing them could not recover evidence that was outside the ROI.

## Implemented correction

The production measurement stage now performs bounded per-capture printed-bubble registration on canonical grayscale pixels before computing neighbor masks or bubble measurements.

1. Each PageLayout bubble supplies the expected center and printed radius.
2. A bounded connected-component search proposes a nearby printed circle. Local paper intensity, radius bounds, aspect ratio, circular outline coverage, and outside-ring contrast validate the proposal. The locator requires exactly one candidate and never selects the darkest or nearest candidate from an ambiguous set.
3. Each layout column is fitted independently. A deterministic robust affine displacement fit uses circle centers only, rejects outliers, and requires distributed question rows.
4. Alternating whole question rows are withheld from fitting. Their prediction error must remain within the configured sampling budget. A row translation can override the affine prediction only when at least three outlines validate it by leave-one-out checks.
5. Corrections are limited to one printed radius, stay within observed convex support, preserve target association and spacing, and stay within the canonical image.
6. Every mask for a target moves together: printed center, interior ROI, baseline annulus, label exclusion, and neighbor exclusion. The published PageLayout remains immutable.
7. Missing, ambiguous, unsupported, or excessive registration evidence returns `BUBBLE_REGISTRATION_UNTRUSTWORTHY` and requests a rescan.

All ratios and bounds are held in `BubbleRegistrationConfig`. Mark classification thresholds and the P15.6 typed preprocessing pipeline were unchanged. The existing label-center exclusion ratio was retained: the controlled no-exclusion replay increased false and ambiguous evidence, including on the blank sheet.

The tilted mixed capture regressed by one question count because Q9 became blank and Q10 ambiguous while Q11 changed from a wrong option to the correct option. The acceptance policy therefore still rejects it. The correction does not silently guess weak marks.

`blank_tilted.jpg` contains two detections for marker ID 13. The new alignment filter enumerates only this narrow single-duplicate case and applies the normal correspondence, four-point residual, and page-geometry validation to both alternatives. Exactly one passed; the other failed `PAGE_BOUNDS_IMPLAUSIBLE`. Registration then rejected the capture because its smoothly curved bubble displacement could not pass the affine held-row validation. The old path classified many false marks, so the fail-closed result is the safe outcome.

`all_marked.jpg` still lacks required marker ID 12. A local native-resolution crop was retried with subpixel and no-refinement detector profiles; neither decoded any marker. No marker corner was predicted or fabricated, and alignment remains rejected.

## Performance

The direct registration durations in the final Android profile replay were 16.745, 14.796, 14.429, and 17.327 ms; median 15.771 ms. End-to-end paired times are dominated by alignment and preprocessing variability, so no overall speedup is claimed. The canonical image hashes matched between registered and baseline runs for each capture, confirming that the experiment changed ROI placement rather than alignment or preprocessing pixels.

## Validation

- `flutter analyze --no-pub`: no issues.
- Focused recognition and ArUco suite: 58 tests passed.
- `flutter test --no-pub`: 772 tests passed, 30 native OpenCV host tests skipped because the Windows native symbols were unavailable.
- Android profile replay: six original JPEGs, unchanged artifact hash `422052171b90f79e1d3c19060e41975cece2a9daa07e872ef7e330b06637c392`.
- Synthetic registration coverage includes affine drift, held-out rows, missing inner and outer support, false circles, independent columns, paper intensity changes, neighboring circles, full/half/crescent/dot/X/faint marks, mask-center consistency, and verified zero-shift geometry.
- Duplicate-marker coverage includes a sole valid interpretation and two valid interpretations; the latter remains rejected.

## Remaining limits

The physical evidence covers one printer/scaling path, one packet layout, and one Android device. Seven weak-stroke questions remain blank or ambiguous across the mixed captures. The production policy correctly requests review/rescan for them. Broader validation still needs multiple printers, actual-size printing, more devices, and the full physical acceptance matrix. The implementation does not claim universal printed-circle detection or production completion beyond this bounded recovery.
