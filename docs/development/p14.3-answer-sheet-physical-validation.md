# P14.3 Answer-Sheet Physical Validation

## Observed failure

During p14.2 printed-sheet testing, the seventh physical response row was
recognized, but the result screen omitted Q7 and presented the detected answer
as Q8. The mark pixels and bubble classification were valid. The failure was in
the identity information available after classification.

## Root cause

`PageLayout` correctly assigned every `QuestionRegion` an explicit
`questionId` and one-based `questionNumber`, and every `BubbleRegion` retained
its `questionId`. Classification preserved `questionId`, but discarded the
region's `questionNumber`. `ScanResult` and the scanner result UI therefore had
no authoritative physical ordinal. The UI rendered classifications in received
list order and labeled them through the matching `TemplateQuestion` prompt.

That contract was insufficient at a schema/group boundary: the detected mark
could retain a semantic ID while the screen or a downstream stored-response
consumer associated it with the next visible question label. There was no
result-level invariant capable of proving that the classified/stored Q7 was
still physical question number 7.

Question identity must not be reconstructed from a list index, group index,
bubble index, or an `index + 1` expression. Stable IDs also do not have to
contain their display number. The authoritative pair is the
`QuestionRegion.questionId` and `QuestionRegion.questionNumber` generated from
template order.

## Fix

- `QuestionClassification` now carries the explicit `questionNumber` copied
  from its authoritative `QuestionRegion`.
- `OfflineScannerEngine` validates both ordered question IDs and ordered
  question numbers against the exact supplied `PageLayout`. A Q7-to-Q8 ID or
  number drift fails with `SCAN_RESULT_INVALID`.
- The result UI sorts numerically by the stored `questionNumber`, displays that
  number, and keys each row by it. It no longer invents a displayed number from
  the visible list position.
- Debug diagnostic JSON and physical-validation records expose both
  `questionId` and `questionNumber`, making the layout, measurement,
  classification, stored-result, and display mapping inspectable without
  production logging.
- Published artifacts continue to supply their stored `PageLayout`; scanner
  resolution does not regenerate geometry from current defaults.

## Compact row spacing

The answer-sheet number lane was reduced from 8 mm to 5 mm. The existing 1.5 mm
minimum content gap remains between the number region and first bubble, and the
5 mm bubble diameter is unchanged. Bubble clearance, safe bounds, marker
exclusions, and all scanner coordinates continue to come from `PageLayout`.

## Regression coverage

The p14.3 fixtures cover:

- compact, non-overlapping number-to-bubble spacing;
- continuous Q1-Q8 numbering across a single-choice to multiple-choice group
  transition;
- a physical Q7-only mark producing only `questionId=q7`, `questionNumber=7`;
- the reverse Q8-only case;
- rejection of an explicit question-number/ID mismatch;
- schema headings not consuming question numbers;
- numeric continuity and ID binding across multiple answer-sheet pages;
- scanning through an immutable published artifact's stored `PageLayout`;
- UI presence and numeric order of Q1 through Q8, including Q7 and Q8;
- existing labeled-bubble recognition behavior through the full test suite.

## Remaining physical validation

The code regression is deterministic, but another physical print/camera pass is
still required. Confirm that the 5 mm number lane is readable on the target
printers, the 1.5 mm gap remains visually clear, and marked physical Q7 and Q8
appear under their matching result rows on representative Android devices.
