# P13.8 Physical Bubble Classification Calibration

## Observed failure

On a fresh printed dense A4 sheet, untouched bubbles frequently became
`AMBIGUOUS`, while real fills could alternate between `MARKED` and
`AMBIGUOUS`. Screen-displayed sheets were less affected than toner, paper
texture, shadows, and small alignment variations on physical paper.

## Root cause

`BubbleEvidenceEvaluator` previously emitted `clearBlank` only when the
combined score was below `minimumCombinedScore` **and no minimum evidence
signal fired**. A harmless threshold crossing in fill ratio, normalized
darkness, or contrast therefore became `conflicting`. At question level, one
such bubble made an otherwise blank or clearly marked exclusive question
ambiguous.

## Revised rules

- A mark still requires corroboration from at least two independent minimum
  evidence signals and the configured combined-score threshold.
- Evidence below that requirement is blank when it contains only weak,
  uncorroborated print/background evidence.
- A single strong but unsupported modality remains `conflicting`; this retains
  review for genuinely contradictory measurements.
- Severe ROI/sample quality remains `INVALID`; non-severe unreliable quality
  remains `AMBIGUOUS`.
- Exclusive questions remain question-relative: no credible candidate is
  `BLANK`; one strong candidate or one sufficiently separated possible
  candidate is `MARKED`; two independently strong candidates are `MULTIPLE`;
  close possible candidates remain `AMBIGUOUS`.
- `minimumTopSecondGap` is applied only when promoting possible evidence or
  checking a possible runner-up against a strong winner. Weak blank noise no
  longer enters that path merely because one minimum signal fired.

## Threshold decision

No recognition thresholds changed in P13.8. In particular,
`minimumTopSecondGap` remains `0.12`. The failure was caused by the evidence
hierarchy, not evidence that physical measurements proved a threshold should
move. Future threshold changes require recorded physical distributions.

## Local validation recorder

The Real Scanner Validation flow recognizes the P13.6 dense v1 fixture and
uses this repeatable known-answer protocol:

- mark Q01 option B;
- mark Q21 option C;
- leave all other bubbles untouched.

The process-local recorder retains template/version/page identity, expected
and detected answers, question top/second/gap values, every bubble's raw and
combined evidence, evidence category, ROI/baseline quality, and scanner stage
timings. The review UI shows compact question evidence and expandable
structured JSON. No cloud or persisted artifact format is involved.

The summary reports total/correct/wrong/ambiguous questions, per-state
accuracy, false-positive marks, false blanks, wrong-confident answers,
accuracy percentage, ambiguity percentage, and average page processing time.
`wrong-confident` excludes `AMBIGUOUS` and `INVALID` outcomes so silent wrong
answers remain visible separately from safe rejection.

## Validation status and assumptions

Automated fixtures cover blank evidence, isolated weak print noise, widespread
outline noise, one credible mark, a dominant possible mark, double strong
marks, close weak candidates, contradictory evidence, and unusable quality.
Synthetic validation does not establish real-paper accuracy.

Physical validation must still record repeated runs using the protocol above
on the Infinix X6711, including strong and light fills, a real double mark,
uniform and one-sided lighting, modest perspective, and at least two print
quality settings. Review the JSON distributions before changing any threshold.
