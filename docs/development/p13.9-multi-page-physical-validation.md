# P13.9 Multi-Page Physical Validation

## Fixture

P13.9 reuses the deterministic P11.1 scanner validation fixture rather than
introducing another layout path:

- Template ID: `p11-1-scanner-validation`
- Template version: `1`
- Layout: existing A4 default profile
- Pages: exactly 3
- Questions by page:
  - page 1: `q1`, `q2`, `q3`, `q4`
  - page 2: `q5`, `q6`, `q7`, `q8`, `q9`
  - page 3: `q10`

The template builder debug screen can generate the exact PDF, publish the
template and its authoritative `PageLayout`, and save the generated PDF.

## Page identity

`PageMarkerIdAllocator` supplies four non-overlapping marker IDs per page:

| Page | PageId | Marker signature |
| --- | --- | --- |
| 1 | `p11-1-scanner-validation-v1-p1` | `10, 11, 12, 13` |
| 2 | `p11-1-scanner-validation-v1-p2` | `14, 15, 16, 17` |
| 3 | `p11-1-scanner-validation-v1-p3` | `18, 19, 20, 21` |

The scanner derives these values from `PageLayout`. It does not hardcode them
or use detector output order. `PageMarkerSignatureResolver` accepts only one
exact four-ID signature. Incomplete, mixed, unknown, and duplicated marker sets
fail with structured errors; there is no closest-page fallback.

## Physical sequence

Use this exact capture order:

1. page 2
2. page 1
3. page 3
4. page 2 again as a duplicate attempt

After page 3 is reviewed, the debug scanner enters a dedicated duplicate-check
step. Align page 2 and use **Capture duplicate Page 2**. The attempt must return
`SCAN_PAGE_ALREADY_COMPLETED`, retain the original page 2 result, keep the
unique page count at three, and then finish the validation session.

## Session invariants

- `resultsByPageId` is authoritative and never overwrites an existing result.
- Out-of-order unique pages are accepted.
- `completedPageCount` counts unique PageIds only.
- `remainingPageIds` is derived from authoritative layout order.
- `isComplete` becomes true only when every required PageId is present.
- `orderedResults` always follows page 1, page 2, page 3 layout order,
  independently of capture order.
- Results with a wrong template, version, or unknown PageId cannot enter the
  session.
- A completed PageId returns a typed duplicate outcome even during the final
  duplicate-check state.

## Validation evidence and metrics

Each terminal capture attempt records template/version, expected and detected
PageId, detected marker IDs, capture sequence, outcome, duplicate/accepted
flags, rejection code, processing duration, unique completed count, and missing
PageIds.

The final debug summary reports required pages, unique accepted pages,
duplicate attempts, wrong-page detections, rejected identity attempts,
completion, authoritative final page order, and total/average processing time.
The acceptance gate is **zero wrong-page detections**.

## Remaining physical validation

On the Infinix X6711:

1. Publish and save the multi-page fixture from the template builder.
2. Print all pages at actual size; do not use fit-to-page scaling.
3. Select the exact published P11.1 v1 artifact in Real Scanner Validation.
4. Scan page 2, review it, and continue.
5. Scan page 1, review it, and continue.
6. Scan page 3 and choose the duplicate-check action.
7. Align page 2 again and tap **Capture duplicate Page 2**.
8. Confirm three unique accepted pages, one duplicate attempt, zero wrong-page
   detections, completion `yes`, and final order page 1/page 2/page 3.
9. Repeat once with moderate perspective and once with one-sided lighting.

Automated validation proves deterministic contracts only. Multi-page physical
validation is not passed until this sequence succeeds on the printed sheets and
device.
