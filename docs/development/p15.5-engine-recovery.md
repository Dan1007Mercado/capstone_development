### Current confirmed issues, ranked

1. **Avoidable alignment work**, originally `83e3338`, redundant for the default
   policy after `1de8b54`: `ArucoAlignmentEngine.align` fits/validates multi-point
   even though `_selectMethod` must select accepted four-point. Existing baseline
   tests explicitly observed two calls. Correction: evaluate multi-point only
   when four-point is unsafe/unavailable or the existing preference requires it.
   No acceptance threshold, marker check, or geometry validator changed.
2. **Replay comparison coupled to production configuration**, introduced by
   the production comparison in `3a3c4f4`, exposed by restored baseline policy:
   `ArucoCaptureReplayHarness.run` uses `currentMultiPointConfig` for both runs.
   With lazy production fitting, that would omit the comparison candidate.
   Correction: separate `productionConfig`; CLI/app replay explicitly request
   multi-point preference for the experiment and retain their production config.
   The comparison still uses normal validation and can fall back; it is not a
   forced acceptance or a strictly multi-point-only scanner.
3. **Baseline verification drift**: `scanner_config_codec.dart` is unformatted;
   `roi_diagnostic_history_test.dart` and three native integration expectations
   still assume the old default. The policy assertion dates to `95aeae3` and
   becomes stale at `1de8b54`. Correct formatting and expected baseline identity;
   preserve assertions about selected diagnostics and geometry. Native changes
   cannot be executed on this host.

The historical rejection mechanism is confirmed independently: all-corner
consistency rejected geometrically valid four-point estimates before warp.
P15.4 already fixes that path; P15.5 does not relax it further.

## C. Unconfirmed hypotheses and accuracy baseline

No measured physical answer accuracy, blank false-selection rate, faint-mark
recall, or deliberate multiple-selection rate is available. The repository's
one apparently blank photograph is not a substitute for a verified answer plan.
Blank/single/multiple/dense/tilted physical acceptance comparisons remain blocked
by missing labeled captures and native runtime/device access.

For labeled answer-sheet layouts, center exclusion is `0.5 * printedRadius`;
interior radius is `0.68 * printedRadius`. Thus the sampled annulus spans
0.5–0.68 radii and covers 0.2124 of the full disk area, before pixel discretization.
This explains sensitivity to placement but does **not** prove label-induced
false marks or missed faint marks. Exclusion belongs to PageLayout, not scanner
configuration. Changing published geometry would also affect old printed sheets.

Normalized grayscale feeds local contrast; binary foreground is exactly 1 for
ink and 0 for paper. Measurement excludes baseline foreground/neighbors and uses
the 70th percentile paper baseline. Classification combines coverage, darkness,
distribution, quality, question semantics, and score separation. It retains
BLANK/MARKED/MULTIPLE/AMBIGUOUS/INVALID. No thresholds or ROI dimensions changed.

Normalization, denoising, and adaptive thresholding could remove marking
evidence; only paired captures and verified ROIs can establish that here.
Full-image temporary allocations in `_clippedLocalMean` and resuming live analysis
during final scanning are profiling candidates, not established latency causes.

## D. Component compatibility assessment

| Boundary | Verified implementation / remaining limit |
|---|---|
| Camera → live analysis | `_onFrame` drops busy/throttled frames before materialization; compact luma is transferred to a persistent worker. Preview and analysis remain separate. Real FPS requires a device. |
| Tracking → readiness/overlay | Current worker always performs ArUco; optional paper edges are tracked separately. Coordinator reset/resume uses fresh state. Existing geometry/tracking/overlay tests cover software contracts; visual device verification is outstanding. |
| Still → marker detection | One grayscale JPEG decode per production session; detection resizes once and remaps pixel centers to original dimensions. Backend declares still orientation applied; actual camera/EXIF behavior needs Android capture validation. |
| Marker detection → registration | IDs resolve roles; marker-local corner order is preserved. Missing/duplicate/wrong signatures, reflection, convexity, size and spacing checks remain active. Both estimates share detections and PageLayout targets. |
| Homography → canonical image | Numeric/page-boundary/local-scale validation is unchanged. Only selected H is warped, into declared canonical dimensions. Native session and temporary Mats have explicit disposal. |
| Canonical image → preprocessing | Owned row-major 8-bit grayscale avoids PNG encoding/decoding in production. Native preprocessing returns detached grayscale/normalized buffers and 0/1 binary; no second JPEG decode. Native parity is unverified on this host. |
| Preprocessing → measurement → classification | Dimension checks, centralized physical-to-canonical mapper, exact target identity and question structure validation. Synthetic tests cover supported types; they cannot establish physical ROI placement. |
| Result → diagnostics/UI | Selected H supplies warp and residuals. Skipped multi-point has no candidate/error and zero estimator duration. Failures remain structured; no fabricated scan success is introduced. |

The persistent final scanner reuses its detector; production does not invoke the
development replay harness. The harness intentionally decodes separate comparison
runs. Production still has one warp, one preprocessing, and one recognition pass.
Existing `candidateValidationDuration` spans optional estimation as well as
validation; do not sum it with homography time as disjoint stages.

Archive failure diagnostics record four-point mean/max residuals 3.686/12.603 px
and multi-point 3.279/8.961 px, with both numerical/geometry checks passing.
These differ from the user's later P15.3.1 values (4.869/19.888 and 4.109/16.878).
They must not be conflated. Recorded stage times were decode 38.493 ms, preparation
26.995 ms, detection 273.201 ms, remap 3.457 ms, four-point fit 2.652 ms,
multi-point fit 4.090 ms, aggregate candidate validation 13.805 ms and alignment
386.848 ms. They describe that historical rejected attempt, not a P15.4 benchmark
or P15.5 before/after latency comparison.

The added archived-correspondence regression injects stored detections/matrices
into the test backend. Baseline selects the identical stored four-point matrix.
Under the archived preference config, the existing localized-uncertainty rule
accepts multi-point, but baseline remains selected. This tests policy and geometry
only; its stub warp does not produce or validate actual canonical pixels.

No independently measured bubble-position advantage supports enabling multi-point
preference in production. Keep the existing hybrid as baseline plus validated
fallback. Required same-JPEG four-point/multi-point/hybrid native comparisons and
answer/position error measurements are not completed on this host. Replay now
retains the alternate experiment even when production skips it; no matrix
averaging, double production warp, or double preprocessing was added.
