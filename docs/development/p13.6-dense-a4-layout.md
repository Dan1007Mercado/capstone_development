# P13.6 Dense A4 Layout

## Profile architecture

`LayoutProfile` makes density an explicit layout-generation choice. The
comfortable path remains `LayoutConfig.a4Default()` and the dense path is
`LayoutConfig.a4Dense()`; `LayoutConfig.forProfile(...)` is the shared typed
factory. No profile is inferred from question count and no mutable global
layout setting exists.

The dense profile is consumed only by `LayoutEngine`. Each resulting
`PageLayout` now exposes its authoritative `contentColumnRegions`, while each
`SectionRegion` and `QuestionRegion` identifies its assigned column. A null
column index represents a deliberate full-width fragment. PDF rendering and
scanner measurement continue to consume this geometry without dense-specific
position calculations.

The typed profile/config can later be stored with an immutable publication.
P13.6 does not add that persistence: the existing publication resolver remains
fixed to the comfortable default unless an explicit config is supplied.

The four ArUco marker dimensions, quiet zones, role mapping, registration
points, starting IDs, and per-page allocation are identical to the comfortable
profile. Bubble diameter also remains at 5 mm; density comes from reserved-area
reduction, tighter deterministic spacing, compact option pitch, and columns.

## Column and pagination strategy

Flow is deterministic and semantic-order preserving:

1. place a section lead in the active column;
2. place complete questions from top to bottom;
3. continue the same section in the next column without repeating its lead;
4. continue on the next page after the last column;
5. assign the next page-specific ArUco signature normally.

Short single-choice, multiple-choice, yes/no, Likert, and fitting numeric-grid
questions may use a column. A prompt exceeding two estimated column lines, a
grid wider than the column, or options that cannot remain horizontal is planned
against full safe width instead. A fitting full-width question receives a
dedicated page fragment; this conservative rule avoids mixing full-width and
partially filled columns. A question that also cannot fit full width returns
`QUESTION_TOO_LARGE` rather than clipping.

Section IDs and QuestionIds are never derived from display text. Continuation
fragments retain their SectionId and omit title, instruction, and
human-readable lead regions. A new semantic section receives its lead exactly
once.

## Geometry validation

Layout generation rejects invalid geometry before returning a document. The
validation covers column bounds and overlap, column assignment, section
fragment overlap, question overlap, question/section-lead overlap, bubble
containment and overlap, marker intersections, safe/page bounds, and marker
registration consistency. Physical and normalized bubble centers continue to
come from centralized geometry conversion.

## Fixture results

The deterministic stress fixture contains 40 single-choice questions, four
options per question, and two sections. With the current constants:

- comfortable profile: 4 A4 pages
- dense profile: 1 A4 page
- dense page question distribution: 20 in column 1 and 20 in column 2
- dense bubbles: 160, all 5 mm
- generated dense PDF: 1 page

A 41-question variant verifies second-page continuation and marker IDs
14/15/16/17. A mixed fixture covers single choice, multiple choice, five-point
Likert, and yes/no questions. Long prompts and a 15-column numeric grid verify
safe full-width fallback.

## Default regression guarantee

`LayoutConfig.a4Default()` retains every prior comfortable numeric value and
uses one column. Existing exact-coordinate tests still produce the original
top-left marker, question, and bubble rectangles, and existing pagination
behavior remains unchanged.

`PdfEngine` was not given any profile branch or alternative positioning logic.
Its render plan uses the exact dense `PageLayout` section, question, bubble,
marker, identity, and header geometry. Scanner configuration and recognition
code were not changed.

## Debug validation entry

The debug template builder exposes **Generate Dense Validation PDF**. It builds
the 40-question fixture through `LayoutEngine` with `a4Dense()`, renders it
through the existing `PdfEngine`, and makes the resulting artifact available to
the existing save action.

## Limitations and physical validation

Dense text sizing still relies on deterministic character-count estimates, not
font shaping inside LayoutEngine. Full-width fallback deliberately favors safe
pagination over reclaiming remaining column space. The reduced spacing, option
labels, 5 mm bubbles, and 1.5 mm marker/content clearance require actual-size
printing and phone-camera scans across multiple printers and Android devices
before the profile can be considered physically validated.
