# p14.2 Answer-Only OMR Sheet

## Why this mode exists

p14.2 separates the respondent-facing questionnaire from the scanner-facing
answer sheet. The questionnaire owns full prompts and response wording. The OMR
answer sheet prints only section headings, compact response-schema headings,
question numbers, and scanner targets. p14.1 remains available as the
prompt-and-bubbles debug/fallback profile.

The current implementation delivers the answer-sheet path. A dedicated
questionnaire renderer remains a follow-up; the semantic `TemplateDefinition`
continues to retain all prompt and option text required by that output.

## Authoritative layout contract

`LayoutConfig.a4AnswerSheet()` is an additive `LayoutProfile.answerSheet`
profile. `LayoutEngine` creates the same `LayoutDocument` / `PageLayout` used by
both `PdfEngine` and scanner composition. The PDF layer never recalculates
bubble positions. `CameraScanContext`, `OfflineScannerEngine`, and recognition
continue to consume the authoritative `PageLayout.bubbleRegions`.

The profile keeps 5 mm bubbles, scanner-safe clearance, marker exclusions, and
adaptive 2/3/4-column candidates. Three columns are preferred; a candidate is
rejected when its answer row cannot fit safely.

## Answer-schema grouping

Consecutive questions within a template section share one group heading when
their answer schema matches. The schema key includes question type and the
compact printed labels, which preserves selection behavior and option shape.
Examples include:

- `LIKERT SCALE 1–5`
- `SINGLE CHOICE A–D`
- `SINGLE CHOICE A–E`
- `YES / NO` or `TRUE / FALSE`
- `MULTIPLE CHOICE A–D — MARK ALL THAT APPLY`
- `NUMERIC GRID 0–9`

A schema change starts a new heading. Section headings remain separate and
question numbering follows exact template order across the document. Full
question prompts, descriptions, section instructions, and external option
labels are not emitted by the answer-sheet PDF plan.

## Labels inside bubbles

`BubbleRegion.printedLabel` carries the compact glyph selected by layout:
letters for choice questions, numeric values for Likert/numeric grids, and
short `Y/N` or `T/F` labels. `PdfEngine` centers a bold, small glyph inside the
authoritative bubble bounds. The glyph command and circle use the same
`BubbleRegion`; no PDF-only bubble geometry exists.

## Recognition strategy

Printed center glyphs are handled with deterministic central exclusion.
Answer-sheet bubbles set
`BubbleRegion.measurementCenterExclusionRatio`. `CanonicalBubbleMapper`
converts that physical contract into `CanonicalBubbleRoi.centerExclusionRadius`.
`BubbleMeasurementEngine` then samples an annulus: pixels inside the configured
center mask are excluded from fill, darkness, and distribution measurements.
The existing local paper baseline and printed-outline exclusion remain in
effect.

This makes an unmarked printed glyph invisible to mark scoring while retaining
the surrounding writable ring. Filled rings, multiple fills, and close partial
marks continue through the unchanged deterministic question classifier and
retain `MARKED`, `MULTIPLE`, and `AMBIGUOUS` outcomes.

## Template Builder integration

`Generate p14.2 Answer Sheet PDF` uses the current active builder definition,
calls `TemplateBuilderController.generatePdfFor` with
`LayoutConfig.a4AnswerSheet()`, and populates the existing layout preview, PDF
result, error, and Save PDF UI. The generic, p14.1 dense, and golden validation
actions remain available.

## Automated validation

Regression coverage verifies:

- grouping boundaries, labels, section preservation, numbering, and ordering;
- omission of prompts and outside labels from the PDF render plan;
- centered bubble-label commands tied to exact bubble bounds;
- deterministic 2/3/4-column layouts and scanner-safe geometry;
- valid `CameraScanContext` identity for every generated page;
- center glyphs classify blank, filled labeled bubbles classify marked, two
  fills classify multiple, and close partial fills remain ambiguous;
- current-template builder generation, preview, result, errors, and saving.

## Physical validation still required

Unit and synthetic tests do not establish production readiness. Print at actual
size and validate multiple printers, paper, and Android devices. The physical
matrix must cover label centering/readability, pencil and pen fillability,
blank labeled circles, faint/heavy fills, checks, X marks, 2/3/4 columns,
multiple sections, mixed schemas, lighting, blur, perspective, and real camera
capture. Tune the center-exclusion ratio only from measured physical evidence
and preserve those scans as regression fixtures.
