# p14.2.1 Published Answer Sheet Artifact

p14.2 creates the answer-sheet geometry. p14.2.1 freezes and publishes that
exact geometry and PDF.

Preview generation is temporary: it validates the current definition and
shows a newly generated answer-sheet layout and PDF. Publication is an
immutable lifecycle transition. It validates a draft, freezes its exact
`TemplateId` and `TemplateVersion`, builds with
`LayoutConfig.a4AnswerSheet()`, renders that exact `LayoutDocument`, and saves
the published definition, `LayoutProfile.answerSheet`, every ordered
`PageLayout`, and the corresponding PDF bytes as one artifact.

The repository rejects overwriting an existing template version. Editing a
published answer sheet therefore starts a new draft revision. Publishing that
revision creates another independently retrievable artifact; older versions
and their PDF and geometry remain unchanged.

Multi-page artifacts preserve page order and each page's `pageIndex`,
`totalPageCount`, `PageId`, template identity, and version. The scanner loads
these stored pages directly into `CameraScanContext`; it does not run
`LayoutEngine` again or reconstruct geometry from current defaults. This keeps
the PDF and scanner tied to the same bubble regions, printed labels, label
measurement masks, question numbers, group headings, and render modes.

The file repository writes the PDF and versioned geometry manifest through a
staging directory and verifies their hashes when reopening an artifact. The
application service performs validation, version checks, layout, and rendering
before its single save call, so failed preparation cannot leave a partial
publication.

Future packet identity must be layered on top of the published artifact
without changing its bubble geometry. Respondent IDs, packet IDs,
questionnaire PDFs, cloud synchronization, and analytics are outside this
phase.
